== The New Typed Command Framework

The replacement is three small generic pieces plus Jakarta validation and Resilience4j retry as cross-cutting concerns.

image::workflow-diagram.svg[Command workflow, 900]

=== The three pillars

1. *`Command<T>`* — a typed envelope carrying a payload of type `T`.
2. *`CommandHandler<REQ, RES>`* — a handler contract with typed input and output.
3. *`CommandDispatcher`* — a central dispatcher that routes commands to handlers.

[source,java]
----
public interface CommandHandler<REQ, RES> {
    RES handle(Command<REQ> command);
}
----

=== What changed compared to legacy

* *Type safety* — requests and responses are typed end-to-end. The compiler catches shape mismatches.
* *Validation at the boundary* — `@Valid` on the DTO fires Jakarta validation before the handler runs.
* *Authorization moved out* — permission checks live in Spring Security's `SecurityConfig`, not in business logic.
* *Retry per command* — every handler carries `@Retry(name = "commandXxxYyy")` with parameters in `application.properties`.
* *Typed Feign client* — regeneration from OpenAPI now produces strong types.
