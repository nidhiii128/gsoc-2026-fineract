== Challenges

=== Quartz scheduler deadlock (PR #10)

After migrating the Job `EXECUTE` endpoint, five `LoanChargeback` integration tests started timing out in CI. Root cause: `@Transactional` on the new handler was deadlocking with Quartz's async job execution — the outer transaction held a lock the job needed.

Fix: remove `@Transactional` from the handler. Later CI runs showed the same tests failing on stock `develop`, so the fix had been protecting against a latent issue that resurfaced elsewhere.

=== The stale "Customer Identifier" code lookup (PR #11)

A `ClientSearchTest` hit 404 in CI on `POST /clients/{id}/identifiers`. The service does:

[source,java]
----
codeValueRepository.findOneByCodeNameAndIdWithNotFoundDetection(
    "Customer Identifier", codeValueId);
----

That lookup requires the CodeValue's parent code to be named exactly `Customer Identifier`. The test was creating code values under a randomly-named code. One-line fix in the test to look up the seeded code by name.

=== Cross-module DTO placement

Some entities (Calendar, for one) live in `fineract-core`. If the typed update method takes a request DTO, the DTO must live in `fineract-core` too — `fineract-core` cannot depend on `fineract-provider`. Cost two hours the first time I hit it.

=== Stacked PR rebases

Calendar UPDATE stacked on CREATE; DELETE stacked on UPDATE. Every `upstream/develop` rebase produced conflicts in the same three files: `SecurityConfig`, `application.properties`, `CommandWrapperBuilder`. Resolution pattern: keep both sides, since each PR adds a distinct endpoint entry.

=== Feign client regeneration

Fineract auto-generates its Feign client from OpenAPI. Every migration that changes an endpoint's response schema changes the client. Integration tests then need typed updates. Usually a mechanical rename, occasionally a signature change.
